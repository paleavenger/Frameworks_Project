# Система управления учебными проектными командами

## Назначение

Система управления учебными проектными командами — учебное приложение для управления проектными командами студентов. Оно помогает собрать команду, назначить участникам роли и быстро оценить готовность команды к началу работы.

Веб-интерфейс Django начат в ПР5, использует шаблоны с ПР6 и данные SQLite с ПР7. В ПР9 страницы переведены на Django ORM, а в ПР10 добавлена административная панель и проверены SQL-запросы. Консольное приложение (ПР1–ПР3) работает с JSON-файлами.

## Используемые технологии

- Python 3.10+ (проверялось на 3.13);
- Django 5.2 — веб-фреймворк;
- Django Template Language (DTL) — шаблоны страниц;
- HTML5 — разметка страниц;
- CSS3 и Bootstrap 5.3 (подключается через CDN) — оформление страниц;
- JavaScript — небольшое клиентское поведение (год в подвале);
- SQLite и Django ORM — хранение и выборка данных веб-интерфейса;
- JSON — хранение данных консольного приложения и источник данных для импорта в SQLite;
- pytest — автоматические тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Студенты, преподаватели и кураторы учебных проектных команд.

## Предметная область

Организация совместной работы над учебными проектами: распределение студентов по командам, назначение ролей и контроль минимального состава команды.

## Основные сущности

Сущности предметной области реализованы классами (пакет `models/`):

| Класс | Атрибуты | Поведение |
| --- | --- | --- |
| `Entity` | `id` | базовый класс: `to_dict()`, `__repr__()` |
| `Student` | `id`, `name`, `specialty` | `matches()`, `to_dict()`, `__str__()` |
| `Project` | `id`, `title` | `to_dict()`, `__str__()` |
| `Role` | `id`, `name` | `to_dict()`, `__str__()` |
| `Membership` | `student`, `role` | `assign_role()`, `to_dict()`, `__str__()` |
| `Team` | `id`, `name`, `project`, `members` | `add_member()`, `remove_member()`, `assign_role()`, `find_member()`, `has_student()`, `is_full()`, `readiness()`, `matches()`, `to_dict()`, `__str__()` |

### Взаимодействие объектов

```text
Team ──project──▶ Project
 └─members─▶ Membership ──student──▶ Student
                  └──────role──────▶ Role (или None, пока роль не назначена)
```

Объекты хранят ссылки друг на друга, а не идентификаторы: `team.project.title`,
`team.members[0].student.name`, `team.members[0].role.name`.

Принципы ООП в проекте:

- **наследование** — `Student`, `Project`, `Role`, `Team` наследуют `Entity`;
- **полиморфизм** — у каждого класса свои `to_dict()` и `__str__()`, а `storage.save_entities()` сохраняет любую сущность одним и тем же кодом;
- **инкапсуляция** — список участников `Team._members` скрыт; снаружи доступен только кортеж `Team.members`, а менять состав можно методами, которые соблюдают ограничения на размер команды.

## Основные функции

1. Добавление, удаление, просмотр, поиск, отбор по специальности и сортировка студентов; статистика по специальностям.
2. Создание и удаление команд, добавление и удаление участников, просмотр состава команд с ролями, просмотр проектов.
3. Назначение ролей и расчёт готовности команды; отбор команд, которые ещё не готовы.
4. Проверка вместимости и доступности (см. правила ниже).
5. Загрузка и сохранение данных в JSON-файлах, обработка ошибок ввода и файлов.

### Правила предметной области

- В команде не более 5 участников (`Team.MAX_SIZE`).
- Студент может состоять только в одной команде (`join_team()`).
- Роль выбирается из справочника ролей (`data/roles.json`): аналитик, разработчик, дизайнер, тестировщик.
- Команда готова к работе, если в ней не менее 3 участников (`Team.MIN_SIZE`) и у всех назначены роли. Процент готовности считается от большего из двух чисел: числа участников и 3.
- Имена студентов, команд, проектов и ролей сравниваются без учёта регистра и крайних пробелов.

### Меню

```text
1. Добавить студента
2. Удалить студента
3. Показать студентов
4. Найти студентов
5. Отобрать студентов по специальности
6. Показать статистику
7. Создать команду
8. Удалить команду
9. Добавить студента в команду
10. Назначить роль
11. Удалить студента из команды
12. Показать команды
13. Найти команды
14. Показать неготовые команды
15. Показать проекты
0. Выход
```

Названия команд, студентов и ролей вводятся целиком (регистр не важен).

### Обработка ошибок

Некорректный ввод в меню не завершает программу. Если файл данных повреждён,
имеет неверную структуру или нарушает правила (ссылка на несуществующего
студента, проект или роль, студент в двух командах, переполненная команда),
программа выводит сообщение и завершается, не перезаписывая файл. Ошибка
записи выводится на экран, работа продолжается.

## Веб-интерфейс (Django)

Django-проект `teamproject` (конфигурация: `settings.py`, корневой `urls.py`) состоит из пяти приложений. Все они зарегистрированы в `INSTALLED_APPS`.

| Приложение | Назначение |
| --- | --- |
| `homepage` | главная страница, обработчик 404, декоратор `with_db` (страница ошибки, если база недоступна), общая статика (CSS, JS, логотип) |
| `students` | страницы студентов, поиск студентов без команды |
| `teams` | страницы команд, поиск команд со свободными местами |
| `projects` | страницы проектов |
| `stats` | страница статистики |

Отдельного приложения для ролей нет: роль — справочник, который показывается внутри страниц студентов и команд. Приложения для пользователей тоже нет: во встроенной модели `User` из `django.contrib.auth` пока нет необходимости, авторизация будет позже.

### Страницы и URL

| URL | View-функция | Что показывает |
| --- | --- | --- |
| `/` | `homepage.views.index` | описание приложения, число объектов, навигация |
| `/students/` | `students.views.students` | список студентов и их команд, поиск по имени (`?q=`) |
| `/students/free/` | `students.views.free_students` | поиск студентов без команды, фильтр по специальности (`?specialty=`) |
| `/students/<int:student_id>/` | `students.views.student_detail` | карточка студента: специальность, команда, роль |
| `/teams/` | `teams.views.teams` | список команд с поиском, фильтром по проекту, сортировкой и пагинацией |
| `/teams/vacancies/` | `teams.views.team_vacancies` | поиск команд, где свободно не менее N мест (`?places=`) |
| `/teams/<int:team_id>/` | `teams.views.team_detail` | карточка команды: проект, участники и роли, готовность |
| `/projects/` | `projects.views.projects` | список проектов и число команд |
| `/projects/<int:project_id>/` | `projects.views.project_detail` | карточка проекта и его команды |
| `/statistics/` | `stats.views.statistics` | показатели: итоги, специальности, роли, готовность команд |

Если студент, команда или проект с указанным `id` не найдены, возвращается страница с кодом 404 («Студент не найден» и т. п.). Для любого адреса без маршрута корневой `urls.py` подключает собственный обработчик `handler404 = "homepage.views.page_not_found"`; его работу видно при `DEBUG = False`.

### Именованные маршруты и пространства имён

У каждого приложения в `urls.py` задан `app_name`, а маршруты имеют имена `list` и `detail` (у главной — `index`). Ссылки в шаблонах строятся тегом `{% url %}`, адреса в HTML не прописаны вручную:

| Имя маршрута | Адрес |
| --- | --- |
| `homepage:index` | `/` |
| `students:list`, `students:detail` | `/students/`, `/students/<id>/` |
| `students:free` | `/students/free/` |
| `teams:list`, `teams:detail` | `/teams/`, `/teams/<id>/` |
| `teams:vacancies` | `/teams/vacancies/` |
| `projects:list`, `projects:detail` | `/projects/`, `/projects/<id>/` |
| `stats:index` | `/statistics/` |

### Шаблоны Django

Архитектура веб-части: `SQLite → Django ORM → view → контекст → шаблон → HTML → HTTP-ответ`. View-функции используют ORM-запросы, готовят контекст и вызывают `render(request, "шаблон.html", context)`. HTML в Python-коде не формируется, функции `page()` из ПР5 больше нет.

```text
templates/                          шаблоны уровня проекта (DIRS в settings.py)
├── base.html                       базовый шаблон: каркас, Bootstrap, статика, блоки
├── 404.html                        страница обработчика 404
└── includes/navigation.html        навигация (подключается в base.html)
homepage/templates/homepage/        index.html, data_error.html
students/templates/students/        student_list.html, student_detail.html, free_students.html,
                                    includes/student_card.html, includes/team_badge.html
teams/templates/teams/              team_list.html, team_detail.html, team_vacancies.html,
                                    includes/team_card.html, includes/readiness_badge.html
projects/templates/projects/        project_list.html, project_detail.html,
                                    includes/project_card.html
stats/templates/stats/              statistics.html
```

Что используется:

- **наследование и блоки** — все страницы начинаются с `{% extends "base.html" %}` и переопределяют `{% block title %}` и `{% block content %}`; общая структура страницы в дочерних шаблонах не дублируется;
- **включаемые шаблоны** `{% include %}` — навигация, карточки студента, команды и проекта, бейджи «команда» и «готовность» (один бейдж готовности используется и в списке, и на карточке команды);
- **контекст** — view передаёт экземпляры моделей, наборы результатов и страницы `Paginator`. Шаблоны обращаются к связанным данным по полям моделей, например `team.project.title` и `member.student.name`;
- **условия и циклы** — `{% if %}` для отсутствующего объекта (страница «не найдено» с кодом 404), для бейджа готовности и пустой команды; `{% for %}…{% empty %}` для списков и состава команды;
- **фильтры** — `length` (число студентов, команд, проектов, участников), `default` (значение, если специальность, роль или название отсутствуют), `truncatechars` (длинное название проекта в карточке); число участников и процент готовности рассчитывают ORM-аннотации;
- **автоэкранирование** Django защищает страницу от разметки в данных.

Если студент, команда или проект с указанным `id` не найдены, view вызывает `render(..., status=404)`, и шаблон показывает сообщение «… не найден». Для адресов без маршрута корневой `urls.py` подключает `handler404 = "homepage.views.page_not_found"` (шаблон `404.html`); его работу видно при `DEBUG = False`.

Декоратор `with_db` в `homepage/views.py` перехватывает ошибки базы Django и показывает шаблон `homepage/data_error.html` с кодом 500 вместо необработанного исключения.

### Статические файлы

Находятся в `homepage/static/homepage/` и подключаются в `base.html` тегом `{% static %}` (в начале файла `{% load static %}`):

| Файл | Назначение | Где используется |
| --- | --- | --- |
| `css/style.css` | собственные стили: карточки, бейджи готовности, навигация, логотип | `base.html`, карточки и бейджи |
| `js/main.js` | выводит текущий год в подвале | `base.html` |
| `img/logo.png` | логотип проекта | `base.html` |

Проверить поиск статики: `python manage.py findstatic homepage/img/logo.png`.

Состав команды и роли можно менять через веб-формы. Создание команд доступно в админ-панели и консольной версии.

## База данных Django ORM (ПР9)

Веб-приложение работает с `db.sqlite3`. Структуру таблиц создают миграции приложений `students`, `projects` и `teams`.

| Модель | Поля и связи |
| --- | --- |
| `students.Student` | `id`, имя, необязательная специальность |
| `projects.Project` | `id`, название, обратная связь `teams` |
| `teams.Team` | `id`, название, `ForeignKey` на проект, студенты через `Membership` |
| `teams.Role` | `id`, уникальное название |
| `teams.Membership` | `id`, команда, уникальная связь со студентом, необязательная роль |

При удалении команды или студента их записи участия удаляются каскадно. Проект с командами и назначенную роль защищает `PROTECT`. Один студент может состоять в одной команде. Миграция `teams/0002_membership_capacity` задаёт триггеры SQLite, которые соблюдают лимит в пять участников при добавлении и переводе. Команда готова при наличии минимум трёх участников с назначенными ролями. Процент рассчитывается как число назначенных ролей, делённое на большее из числа участников и трёх.

### Перенос из ПР7

`python manage.py import_pr7` читает `data/teams.sqlite` в режиме только чтения. Для другого файла передайте `--source ПУТЬ`. Команда проверяет внешние ключи источника и переносит студентов, проекты и роли, затем команды и записи участия с исходными ID. Все целевые записи сохраняются в одной транзакции. Повторный запуск с теми же данными безопасен. При конфликте с уже изменёнными записями импорт завершается без частичного переноса.

Консольное приложение продолжает использовать JSON. Если в новой копии проекта нет базы ПР7, её можно первоначально собрать из JSON командой `python -m db.import_json`. Эта команда заново заполняет базу ПР7. Файлы `sql/schema.sql`, `sql/queries.sql` и модуль `db/` описывают этот прежний этап. SQL-примеры можно выполнить в SQLite CLI с помощью `.read sql/queries.sql` после открытия `data/teams.sqlite`.

### Запросы ORM в веб-интерфейсе

| Страница | Выборки и операции |
| --- | --- |
| `/` | Три запроса `count()` по студентам, командам и проектам |
| `/students/`, `/students/<id>/` | Список и карточка по `get()`; `select_related()` для команды и роли; поиск по имени `?q=` |
| `/students/free/` | `filter(membership__isnull=True)`, дополнительный `specialty`, список специальностей через `exclude()`, `values()` и `distinct()` |
| `/teams/`, `/teams/<id>/` | Список, карточка, состав с ролями и проектом; поиск по названию команды или проекта `?q=`, фильтр по ID проекта `?project=`, сортировка `?sort=name\|project\|readiness`, пагинация по пять команд `?page=` |
| `/teams/vacancies/` | Подсчёт участников и свободных мест через `annotate()` и `F()`, отбор команд по минимальному числу мест `?places=` |
| `/projects/`, `/projects/<id>/` | Число команд через `annotate(Count(...))`, карточка проекта, список команд по обратной связи |
| `/statistics/` | Счётчики, округлённое среднее через `aggregate(Avg(...))`, группировка по специальности и роли, топ команд, проекты с несколькими командами и неготовые команды |

Поиск по названиям и именам учитывает регистр через Unicode-приведение к одному регистру. При переходе между страницами сохраняются поиск, фильтр и сортировка. При неверном значении сортировки используется порядок по названию. CRUD и ограничения связей проверяются на временной базе в `tests/test_orm.py`.

## Администрирование и проверка ORM (ПР10)

Админ-панель находится по адресу `/admin/`. Создайте локального суперпользователя командой `python manage.py createsuperuser`. Для ограниченного доступа создайте группу, например «Просмотр студентов», дайте ей право просмотра студентов и назначьте группу сотруднику с доступом в админ-панель.

Доступны студенты, проекты, команды, роли и записи участия. Списки поддерживают поиск, сортировку и постраничный вывод. Студентов можно фильтровать по специальности, команды по проекту и состоянию, а состав по команде и роли. В карточке проекта видны его команды, в карточке студента — участие с командой и ролью. Роль можно изменить в составе команды или прямо в списке участия. Для добавления студента в команду используйте «Состав команд».

На `/teams/` параметр `status` принимает `empty` (пустая команда), `forming` (формируется) или `ready` (минимум три участника и у всех назначены роли). Состояние рассчитывается по составу через `TeamQuerySet` и используется при фильтрации и в статистике. При наличии свободных мест команда доступна для набора независимо от состояния готовности.

Ссылки на проекты в списке формируются через `get_absolute_url()` и ведут на `/projects/p/<slug>/`. Миграция назначила уникальные адреса существующим проектам. При переименовании адрес сохраняется. Адреса вида `/projects/<id>/` остаются действительными.

Для просмотра SQL локально включите Django Debug Toolbar в PowerShell:

```powershell
$env:DJANGO_DEBUG_TOOLBAR = '1'
python manage.py runserver
```

Откройте страницу на `http://127.0.0.1:8000/` и выберите **SQL** на панели. На списке команд ожидаются три запроса — перечень проектов, подсчёт результатов и выборка страницы. Карточка команды делает два запроса — команда с проектом и участники со студентами и ролями. Статистика выполняет девять запросов вместо одиннадцати благодаря условным агрегатам. Для выключения панели удалите переменную командой `Remove-Item Env:DJANGO_DEBUG_TOOLBAR` и перезапустите сервер.

## Веб-формы и изображения (ПР11)

- `/teams/` использует форму Django для поиска по названию команды или проекта, фильтров по проекту и состоянию, сортировки. Форма выводит ошибки у полей. Корректные параметры продолжают действовать при ошибке в другом поле. Ссылки пагинации сохраняют параметры запроса.
- В карточке команды войдите через ссылку «Войти для управления составом». С учётной записью сотрудника и разрешениями `add_membership`, `change_membership` или `delete_membership` доступны соответствующие кнопки. Новый участник добавляется в открытую команду. При редактировании можно поменять роль или перевести студента в другую команду. Один студент может состоять только в одной команде. Форма и база проверяют лимит в пять участников.
- Удаление участия выполняется POST-запросом с CSRF-токеном. Студент снова доступен для набора, а число свободных мест увеличивается.
- В карточке проекта сотрудник с разрешением `change_project` может загрузить, заменить или очистить изображение. То же поле находится в карточке проекта в админ-панели. Принимаются PNG, JPEG и WebP до 5 МБ. Файлы хранятся в `media/projects/`, а в базе хранится путь. Локальный сервер обслуживает URL `/media/` при `DEBUG=True`.

Для существующей базы выполните `python manage.py migrate`. Пустое поле изображения не влияет на существующие карточки. Зависимость Pillow устанавливается командой `pip install -r requirements.txt`.

### Формат данных

В JSON хранятся только данные; связи между объектами записываются
идентификаторами. При загрузке `storage.py` находит объекты по `id` и
создаёт ссылки. JSON-файлы используются консольным приложением и как
источник данных для `db/import_json.py`.

`data/students.json`:

```json
[{"id": 1, "name": "Анна", "specialty": "аналитика"}]
```

`data/projects.json`:

```json
[{"id": 1, "title": "Электронный журнал посещаемости"}]
```

`data/roles.json`:

```json
[{"id": 1, "name": "аналитик"}]
```

`data/teams.json` (`role_id` равен `null`, пока роль не назначена):

```json
[{
  "id": 1,
  "name": "Команда Альфа",
  "project_id": 1,
  "members": [{"student_id": 1, "role_id": 1}]
}]
```

Файлы читаются и записываются через контекстный менеджер `with`; запись
выполняется через временный файл, чтобы не повредить данные при сбое.

## Запуск

Установка зависимостей (в виртуальном окружении):

```text
pip install -r requirements.txt
```

Веб-приложение:

```text
python manage.py migrate
python manage.py import_pr7
python manage.py check
python manage.py runserver
```

Для первого запуска без файла `data/teams.sqlite` выполните перед импортом `python -m db.import_json`.

После запуска откройте http://127.0.0.1:8000/.

Консольное приложение:

```text
python main.py
```

Для запуска тестов:

```text
pytest
```

Для проверки стиля:

```text
flake8
```

Тесты проверяют веб-страницы, перенос данных, CRUD, правила предметной области, SQL из ПР7 и консольные сценарии. Тестовые базы создаются во временном каталоге.

Для запуска в PyCharm нужно выбрать интерпретатор `Python 3.13 (PR1_Frameworks)` из каталога `.venv` и запустить файл `main.py`.
