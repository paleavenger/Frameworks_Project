# Система управления учебными проектными командами

## Назначение

Система управления учебными проектными командами — учебное приложение для управления проектными командами студентов. Оно помогает собрать команду, назначить участникам роли и быстро оценить готовность команды к началу работы.

Консольное приложение (ПР1–ПР3) дополнено веб-интерфейсом на Django: страницы (ПР5) переведены на систему шаблонов Django (ПР6). Данные пока хранятся в JSON-файлах и общие для обеих версий.

## Используемые технологии

- Python 3.10+ (проверялось на 3.13);
- Django 5.2 — веб-фреймворк;
- Django Template Language (DTL) — шаблоны страниц;
- HTML5 — разметка страниц;
- CSS3 и Bootstrap 5.3 (подключается через CDN) — оформление страниц;
- JavaScript — небольшое клиентское поведение (год в подвале);
- JSON — хранение данных (Django ORM пока не используется);
- pytest — автоматические тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Студенты, преподаватели и кураторы учебных проектных команд.

## Предметная область

Организация совместной работы над учебными проектами: распределение студентов по командам, назначение ролей и контроль минимального состава команды.

## Основные сущности

Сущности предметной области реализованы классами (пакет `models/`):

| Класс | Атрибуты | Поведение |
| --- | --- | --- |
| `Entity` | `id` | базовый класс: `to_dict()`, `__repr__()` |
| `Student` | `id`, `name`, `specialty` | `matches()`, `to_dict()`, `__str__()` |
| `Project` | `id`, `title` | `to_dict()`, `__str__()` |
| `Role` | `id`, `name` | `to_dict()`, `__str__()` |
| `Membership` | `student`, `role` | `assign_role()`, `to_dict()`, `__str__()` |
| `Team` | `id`, `name`, `project`, `members` | `add_member()`, `remove_member()`, `assign_role()`, `find_member()`, `has_student()`, `is_full()`, `readiness()`, `matches()`, `to_dict()`, `__str__()` |

### Взаимодействие объектов

```text
Team ──project──▶ Project
 └─members─▶ Membership ──student──▶ Student
                  └──────role──────▶ Role (или None, пока роль не назначена)
```

Объекты хранят ссылки друг на друга, а не идентификаторы: `team.project.title`,
`team.members[0].student.name`, `team.members[0].role.name`.

Принципы ООП в проекте:

- **наследование** — `Student`, `Project`, `Role`, `Team` наследуют `Entity`;
- **полиморфизм** — у каждого класса свои `to_dict()` и `__str__()`, а `storage.save_entities()` сохраняет любую сущность одним и тем же кодом;
- **инкапсуляция** — список участников `Team._members` скрыт; снаружи доступен только кортеж `Team.members`, а менять состав можно методами, которые соблюдают ограничения на размер команды.

## Основные функции

1. Добавление, удаление, просмотр, поиск, отбор по специальности и сортировка студентов; статистика по специальностям.
2. Создание и удаление команд, добавление и удаление участников, просмотр состава команд с ролями, просмотр проектов.
3. Назначение ролей и расчёт готовности команды; отбор команд, которые ещё не готовы.
4. Проверка вместимости и доступности (см. правила ниже).
5. Загрузка и сохранение данных в JSON-файлах, обработка ошибок ввода и файлов.

### Правила предметной области

- В команде не более 5 участников (`Team.MAX_SIZE`).
- Студент может состоять только в одной команде (`join_team()`).
- Роль выбирается из справочника ролей (`data/roles.json`): аналитик, разработчик, дизайнер, тестировщик.
- Команда готова к работе, если в ней не менее 3 участников (`Team.MIN_SIZE`) и у всех назначены роли. Процент готовности считается от большего из двух чисел: числа участников и 3.
- Имена студентов, команд, проектов и ролей сравниваются без учёта регистра и крайних пробелов.

### Меню

```text
1. Добавить студента
2. Удалить студента
3. Показать студентов
4. Найти студентов
5. Отобрать студентов по специальности
6. Показать статистику
7. Создать команду
8. Удалить команду
9. Добавить студента в команду
10. Назначить роль
11. Удалить студента из команды
12. Показать команды
13. Найти команды
14. Показать неготовые команды
15. Показать проекты
0. Выход
```

Названия команд, студентов и ролей вводятся целиком (регистр не важен).

### Обработка ошибок

Некорректный ввод в меню не завершает программу. Если файл данных повреждён,
имеет неверную структуру или нарушает правила (ссылка на несуществующего
студента, проект или роль, студент в двух командах, переполненная команда),
программа выводит сообщение и завершается, не перезаписывая файл. Ошибка
записи выводится на экран, работа продолжается.

## Веб-интерфейс (Django)

Django-проект `teamproject` (конфигурация: `settings.py`, корневой `urls.py`) состоит из четырёх приложений. Все они зарегистрированы в `INSTALLED_APPS`.

| Приложение | Назначение |
| --- | --- |
| `homepage` | главная страница, обработчик 404, декоратор загрузки данных, общая статика (CSS, JS, логотип) |
| `students` | страницы студентов |
| `teams` | страницы команд |
| `projects` | страницы проектов |

Отдельного приложения для ролей нет: роль — справочник, который показывается внутри страниц студентов и команд. Приложения для пользователей тоже нет: во встроенной модели `User` из `django.contrib.auth` пока нет необходимости, авторизация будет позже.

### Страницы и URL

| URL | View-функция | Что показывает |
| --- | --- | --- |
| `/` | `homepage.views.index` | описание приложения, число объектов, навигация |
| `/students/` | `students.views.students` | список студентов и их команд |
| `/students/<int:student_id>/` | `students.views.student_detail` | карточка студента: специальность, команда, роль |
| `/teams/` | `teams.views.teams` | список команд: проект, состав, готовность |
| `/teams/<int:team_id>/` | `teams.views.team_detail` | карточка команды: проект, участники и роли, готовность |
| `/projects/` | `projects.views.projects` | список проектов и число команд |
| `/projects/<int:project_id>/` | `projects.views.project_detail` | карточка проекта и его команды |

Если студент, команда или проект с указанным `id` не найдены, возвращается страница с кодом 404 («Студент не найден» и т. п.). Для любого адреса без маршрута корневой `urls.py` подключает собственный обработчик `handler404 = "homepage.views.page_not_found"`; его работу видно при `DEBUG = False`.

### Именованные маршруты и пространства имён

У каждого приложения в `urls.py` задан `app_name`, а маршруты имеют имена `list` и `detail` (у главной — `index`). Ссылки в шаблонах строятся тегом `{% url %}`, адреса в HTML не прописаны вручную:

| Имя маршрута | Адрес |
| --- | --- |
| `homepage:index` | `/` |
| `students:list`, `students:detail` | `/students/`, `/students/<id>/` |
| `teams:list`, `teams:detail` | `/teams/`, `/teams/<id>/` |
| `projects:list`, `projects:detail` | `/projects/`, `/projects/<id>/` |

### Шаблоны Django

Архитектура веб-части: `JSON → объекты → view → контекст → шаблон → HTML → HTTP-ответ`. View-функции только загружают данные, ищут объект, готовят контекст и вызывают `render(request, "шаблон.html", context)`. HTML в Python-коде не формируется, функции `page()` из ПР5 больше нет.

```text
templates/                          шаблоны уровня проекта (DIRS в settings.py)
├── base.html                       базовый шаблон: каркас, Bootstrap, статика, блоки
├── 404.html                        страница обработчика 404
└── includes/navigation.html        навигация (подключается в base.html)
homepage/templates/homepage/        index.html, data_error.html
students/templates/students/        student_list.html, student_detail.html,
                                    includes/student_card.html, includes/team_badge.html
teams/templates/teams/              team_list.html, team_detail.html,
                                    includes/team_card.html, includes/readiness_badge.html
projects/templates/projects/        project_list.html, project_detail.html,
                                    includes/project_card.html
```

Что используется:

- **наследование и блоки** — все страницы начинаются с `{% extends "base.html" %}` и переопределяют `{% block title %}` и `{% block content %}`; общая структура страницы в дочерних шаблонах не дублируется;
- **включаемые шаблоны** `{% include %}` — навигация, карточки студента, команды и проекта, бейджи «команда» и «готовность» (один бейдж готовности используется и в списке, и на карточке команды);
- **контекст** — view передаёт объекты предметной области (`student`, `team`, `project`, списки `entries`, `teams`); шаблон обращается к их атрибутам: `team.project.title`, `member.student.name`, `member.role.name`;
- **условия и циклы** — `{% if %}` для отсутствующего объекта (страница «не найдено» с кодом 404), для бейджа готовности и пустой команды; `{% for %}…{% empty %}` для списков и состава команды;
- **фильтры** — `length` (число студентов, команд, проектов, участников), `default` (значение, если специальность, роль или название отсутствуют), `truncatechars` (длинное название проекта в карточке); фильтры только форматируют вывод, логика остаётся в Python (`Team.readiness_percent` и `Team.readiness_message` — свойства класса);
- **автоэкранирование** Django защищает страницу от разметки в данных.

Если студент, команда или проект с указанным `id` не найдены, view вызывает `render(..., status=404)`, и шаблон показывает сообщение «… не найден». Для адресов без маршрута корневой `urls.py` подключает `handler404 = "homepage.views.page_not_found"` (шаблон `404.html`); его работу видно при `DEBUG = False`.

Декоратор `with_data` в `homepage/views.py` загружает данные функцией `storage.load_data()` и передаёт их во view вторым аргументом. Если файлы повреждены, показывается шаблон `homepage/data_error.html` с кодом 500.

### Статические файлы

Находятся в `homepage/static/homepage/` и подключаются в `base.html` тегом `{% static %}` (в начале файла `{% load static %}`):

| Файл | Назначение | Где используется |
| --- | --- | --- |
| `css/style.css` | собственные стили: карточки, бейджи готовности, навигация, логотип | `base.html`, карточки и бейджи |
| `js/main.js` | выводит текущий год в подвале | `base.html` |
| `img/logo.png` | логотип проекта | `base.html` |

Проверить поиск статики: `python manage.py findstatic homepage/img/logo.png`.

Изменяющие операции консольной версии (создание команд, назначение ролей и т. д.) в веб-интерфейсе появятся вместе с формами. Django ORM и формы пока не используются.

- `teamproject/` — конфигурация Django (`settings.py`, `urls.py`);

- `templates/` — шаблоны уровня проекта (`base.html`, навигация, 404);
- `main.py` — точка запуска консольного меню;

- `tests/` — автоматические тесты `pytest`;
- `pr1_version/` — первоначальная версия ПР1;
- `.flake8` — настройки проверки стиля.

### Формат данных

В JSON хранятся только данные; связи между объектами записываются
идентификаторами. При загрузке `storage.py` находит объекты по `id` и
создаёт ссылки.

`data/students.json`:

```json
[{"id": 1, "name": "Анна", "specialty": "аналитика"}]
```

`data/projects.json`:

```json
[{"id": 1, "title": "Электронный журнал посещаемости"}]
```

`data/roles.json`:

```json
[{"id": 1, "name": "аналитик"}]
```

`data/teams.json` (`role_id` равен `null`, пока роль не назначена):

```json
[{
  "id": 1,
  "name": "Команда Альфа",
  "project_id": 1,
  "members": [{"student_id": 1, "role_id": 1}]
}]
```

Файлы читаются и записываются через контекстный менеджер `with`; запись
выполняется через временный файл, чтобы не повредить данные при сбое.

## План развития

На следующих этапах планируется:

- редактирование студентов и перенос участников между командами;
- формы Django для создания и изменения данных;
- подключение базы данных (Django ORM) вместо JSON;
- реализация пользователей: студентов и преподавателей;
- разработка API;
- контейнеризация приложения;
- настройка CI/CD.

## Запуск

Установка зависимостей (в виртуальном окружении):

```text
pip install -r requirements.txt
```

Веб-приложение:

```text
python manage.py migrate
python manage.py check
python manage.py runserver
```

После запуска откройте http://127.0.0.1:8000/.

Консольное приложение:

```text
python main.py
```

Для запуска тестов:

```text
pytest
```

Для проверки стиля:

```text
flake8
```

Тесты включают проверку маршрутов и страниц Django (`tests/test_web.py`) и консольной версии.

Для запуска в PyCharm нужно выбрать интерпретатор `Python 3.13 (PR1_Frameworks)` из каталога `.venv` и запустить файл `main.py`.
