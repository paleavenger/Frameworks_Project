# Краткий отчёт по проекту TeamProject Manager

## 1. Тема и цель

Проект посвящён системе управления учебными проектными командами. Цель начальной версии — показать базовые операции предметной области: создание команды в памяти программы, добавление студентов, назначение ролей и расчёт готовности команды.

Целевая аудитория — студенты, преподаватели и кураторы учебных проектов. Основные сущности: студент, команда, проект и роль.

## 2. Реализация

Программа написана на Python и находится в файле `main.py`. Реализованы три функции:

- `add_student_to_team()` добавляет участника и не допускает повторное добавление;
- `assign_role()` назначает роль только зарегистрированному участнику;
- `calculate_team_readiness()` считает процент назначенных ролей и возвращает текстовый статус.

В программе использованы словари, строки, целые числа, условия, преобразование результата в `int`, цикл-генератор и импорт стандартного модуля `datetime`. Демонстрационные данные создаются в функции `main()`, поэтому программу можно запускать без ввода с клавиатуры.

## 3. Настройка среды

Для проекта создано виртуальное окружение `.venv` на Python 3.13. В PyCharm выбран интерпретатор `Python 3.13 (PR1_Frameworks)`. Каталог `.venv` и служебные файлы IDE добавлены в `.gitignore`, чтобы в репозиторий попадал только исходный код и документация.

## 4. Отладка

Для отладки в PyCharm был выбран файл `main.py`, поставлен breakpoint на строке с вызовом `calculate_team_readiness(team)`. После запуска через **Debug** выполнение остановилось перед расчётом.

Пошаговый просмотр показал следующие значения:

- `students_count = 3`;
- `assigned_roles = 3`;
- возвращаемый результат — `(100, "Команда готова к работе")`.

В учебных целях в условии готовности была временно допущена ошибка: использовалось сравнение `assigned_roles > students_count`. При трёх назначенных ролях условие не выполнялось, поэтому программа ошибочно сообщала, что нужно назначить роли. Во время пошаговой отладки значение `assigned_roles` было сравнено со значением `students_count`, после чего оператор исправлен на `==`. Повторный запуск показал корректный результат `100%`.
